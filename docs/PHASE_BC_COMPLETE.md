# Phase B/C 收口说明（业务视角）

> 2026-07-27 · 工程切片已收口；**默认停止继续堆企业运维微特性**。

## 1. 你最近看到的改动，到底在干什么？

可以分成三层理解（从对客户有用 → 对销售/交付包装有用）：

| 层级 | 客户真正买什么 | 对应能力 | 最近是否还在加码 |
|------|----------------|----------|------------------|
| **L0 质量可信** | 测了算数、不假绿、能进 CI | 执行诚实、跨端变量/HITL/Risk、报告历史同源、Golden | ✅ 已稳，应作为主线 |
| **L1 能卖给企业 IT** | 私有化、审计、SSO、跨端故事、证据包 | License、审计/SSO、Trace、客户审计包、AgentTeams 本地控制面 | ✅ 已齐到可演示 |
| **L2 运维/规模化包装** | 多机执行节点、调度就绪、队列、SLA 证据 | 执行农场、Worker drain、SLA 样本/告警 | ✅ **雏形已够**；再深挖 ROI 低 |

最近多轮改动主要落在 **L2**：让「企业版并行节点 / 远程桌面 / 运营看板」有可点的页面和诚实 API，避免销售空口说「支持农场」却点不开。  
它们**不替代** Fake ERP / 真实客户 ERP / 一条完整业务流验收。

## 2. 对业务的具体作用（用人话）

| 模块 | 业务作用 | 不是什么 |
|------|----------|----------|
| Trace / Skill 沉淀 | 失败可审计；成功流可沉淀成可复用 Skill 草稿 | 不是自动生成完美用例 |
| 执行农场 + remote 门禁 | 多机/远程桌面时，未就绪就诚实红灯，避免「远程其实没配」却假绿 | 不是已实现大规模并行压测平台 |
| Fan-out / Worker drain | 运维可批量探活节点、消化探测队列 | 不是业务用例已在多机并行跑完 |
| SLA 证据 / 告警 | 给交付/运维看延迟与失败率提示，合同仍另签 | 不是「SLA 已达标」绿灯 |
| SDK runtime 探测 | 赛期/生态叙事可对齐；未装官方 SDK 不装蒜 | 不是已接入厂商完整 runtime |

## 4. 明确不做（避免继续挖深）

在没有**真实客户 PoC / 合同 SLA 条款**之前，默认不做：

1. 常驻 Worker 守护进程 / K8s 调度器  
2. 跨业务用例真并行 fan-out（多机跑完整回归套件）  
3. 邮件/PagerDuty 级合同 SLA 闭环（仅保留可选 Webhook 钩子）  
4. 官方 AgentTeams 厂商 runtime 全量接入（无包则保持 `SDK_NOT_INSTALLED`）  
5. iOS / 云真机  

## 5. 还要不要做很深的业务线？

**现在不需要再深挖 L2 运维线。**

建议优先级：

1. **客户业务验收**：真实/样例 ERP 一条流（已有 Fake ERP + `@erp`）在客户环境跑通并留证  
2. **销售演示脚本**：跨端页一键模板 → Trace → 审计包 → CI curl（讲故事，不讲农场内部队列）  
3. **有合同再做**：多机并行套件、合同 SLA 通道、厂商 SDK runtime  

一句话：**平台底座与企业包装已够卖/够演示；下一刀应是客户业务场景，而不是再加农场按钮。**
