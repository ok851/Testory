# 2026-08-27 工作日志

## 修复 tests/ 旧路径引用（仓库重组后遗症）
- 现象：pytest 一跑即 `ModuleNotFoundError: No module named 'mobile_cross_end_tools'` 等，整张回归安全网失效
- 根因：2026-08-26 仓库重组（173 模块迁入 modules/ 9 域子包、import 重写为 modules.*）时，重组脚本只处理了生产模块与它们的 import，**tests/ 下的字符串引用（mock.patch/__import__/import_module）与 import 语句未被批量改写**
- 修复脚本：基于 modules/ 173 模块名 → `modules.<域>.<模块>` 映射，对 tests/ 全量重写
  - 字符串引用（patch/__import__/import_module）用**整文件级**正则（`[\s\S]*?` 跨行），因为存在多行形式如 `__import__(\n    "desktop_visual_engine"\n)` 与多行 `@patch(\n "mod.func"\n)`
  - import 语句逐行改写（`from X import` / `import X [as Y]` / `import a, b`）
  - 根保留模块（app/database 等 12 个 CLI）、独立顶层包（ai_modules/packages/skills/testory_cli/testory_mcp/web_capture/mobile_engine/...）、第三方/标准库不动
- 结果：43 文件、270 行改；pytest --collect-only **1122 tests collected, 0 error**（修复前 1119 collected + 1 error）；AST 全库 tests/ 177 文件 0 语法错误；无 `modules.modules.` 双写
- 重要踩坑（复用）：旧脚本**逐行 split 处理**会漏跨行引用（`\s` 默认不匹配换行，DOTALL 只影响 `.` 不影响 `\s`）。必须**整文件级正则 + `[\s\S]*?`** 才覆盖多行 `patch`/`__import__`。本次先逐行（漏 1 个多行 __import__）→ 加 DOTALL（仍漏，因 \s 不过换行）→ 加 [\s\S] 仍逐行（仍漏，因已 split）→ 整文件级 + [\s\S]*? 才全过
