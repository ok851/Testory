## 跨端动作性能优化四项落地（承接 8/28 分析）

用户确认「开始实施」后，落地 8/28 给出的跨端性能方案。

### 改动清单
1. **UI 树获取超时收敛**（最坏 ~65s/次 → ~30s/次）：
   - `mobile_automation_gateway/plugin_rpc.py` `get_page_source`：RPC 10s→5s；内部 dump 兜底 20s→10s、cat 15s→8s
   - `modules/mobile/mobile_ui_probe.py` `_adb_uiautomator_dump`：dump 20s→10s、sleep 0.3→0.15、cat 15s→8s
   - `modules/mobile/mobile_agent_client.py` `agent_page_source`：默认 120s → 显式 `timeout_sec=10.0`（三级兜底链原来会被它整体阻塞）
2. **observe 默认误触发 VLM 的 bug（重大发现）**：`_observe_after_action` 旧实现 `str(observe or "")` 把默认 `observe=True` 变成字符串 `"true"` 命中 `("deep","vlm","1","true","yes")` 集合 → **每个 tap/swipe 默认都跑一次 VLM 屏幕概括**（秒级开销），与 docstring「默认只 OCR」相悖。且 `observe=False` 因 `False or ""` → `""` 不命中 off 集合，实际关不掉 OCR。已重写：bool 显式处理，deep 集合收敛为 `("deep","vlm")`，False/None 直接 return {}。
3. **verify/observe 合并**：`_observe_after_action` 新增 `verification` 参数——tap 树级校验 found=True 且非 deep 时返回 `{"observation":{"skipped":"tree_verified"}}`，连截图 OCR 都免（树级校验是真实性根本）。tap 分支传入 `_verify_after_action` 结果；swipe/input 等调用点签名向后兼容（无校验→轻量 OCR）。
4. **get_screen_size TTL 缓存**：`mobile_ui_probe.py` 模块级 `_SCREEN_SIZE_CACHE`（serial → (ts,(w,h))，TTL 60s），此前每个 tap/swipe 注入前都 spawn 一个 ADB 子进程查分辨率。横竖屏切换最多滞后一个 TTL。

### 验证
- 4 个文件 py_compile 通过；整链 import 通过。
- observe 逻辑 5 组断言全过：False→{}；True+tree_verified→skipped；True+not found→走截图（无设备优雅降级，无 vision 字段）；"true" 字符串不再触发 VLM；deep 不被 tree_verified 跳过。
- screen_size 缓存命中/过期回源断言通过。

### 每动作预期收益（tap 定位场景）
- 默认 VLM 误触发：省数秒（最大头）
- tree_verified 免 OCR：省 ~1s
- screen_size 缓存：省 1 次 ADB 子进程 ~0.3-0.5s
- 树获取超时收敛：失败场景最坏耗时减半
