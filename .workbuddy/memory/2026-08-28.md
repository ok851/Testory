### 「agent 一收到命令就报 HTTP 500」二次排查（同日后续）
- 用户报：智能体现在能启动，但一发命令立刻「执行失败: HTTP 500」。
- 链路确认：前端 `static/js/ai_assistant.js:873` 把含「HTTP 500」的消息映射为「服务器内部错误」；字符串来自 `modules/hermes/hermes_gateway_client._http_error_detail` 的 `HTTP {code}`。

## 「关闭软件导致进程卡死」排查与修复

用户报：关闭 Testory 软件时进程卡死、无法像以前那样正常关闭。

### 根因（实证）
- 启动链：Testory.exe → testory_exe_launcher.py → uat_desktop.py（父壳）subprocess.Popen 起后端 app.py → app.py 内部 `_boot_desktop_side_services`/`_boot_mobile_side_services` 线程里 spawn 桌面/移动网关；Hermes 网关由 UI 触发后在 app.py 进程内 spawn。这些都是 **backend 的孙进程**。
- 关闭时 `_shutdown_all(proc)` 在父壳执行：`proc.terminate()`（Windows 即 TerminateProcess，**不递归杀子进程**）→ 后端 app.py 被杀死，但它在进程内 spawn 的 Hermes(8642)/桌面(8766)/移动(8777) 网关变成**孤儿进程**继续存活 → 端口被占、进程管理器里残留、下次启动冲突。父进程 `stop_hermes_gateway`/`stop_desktop_gateway`/`stop_mobile_gateway` 的模块级 `_GATEWAY_PROC` 在父进程中永远是 None（spawn 发生在 app.py 内），根本杀不到这些孙进程。
- 实证：关闭后 `netstat` 显示 5000（后端）已下线，但 8642/8766 仍在 LISTENING（PID 孤儿）。已用 Stop-Process 清理。

### 已修复
- `packaging/uat_desktop.py`：新增 `_kill_process_tree(pid)`（Windows `taskkill /T /F /PID`，其他平台 `os.killpg(SIGKILL)`），在 `_shutdown_all` 中**先递归杀 backend 进程树**（连同 Hermes/桌面/移动网关孙进程），再兜底调用 `shutdown_all_services()` 做端口回收。编译通过。
- 注意：改动在 `packaging/uat_desktop.py`（桌面启动器源码）。若已发布为打包 exe（`dist/uat_release/...`），需重新打包或确保运行时用的是源码布局。
