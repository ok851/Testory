# AI 自主测试页面重构计划

## 1. 需求分析

### 1.1 用户核心诉求

| 需求点 | 说明 |
|--------|------|
| 移除中间画布 | 中间浏览器画布实际意义不大，应让AI直接在用户本地操作（打开有头浏览器） |
| 简化前端操作 | 当前执行逻辑仅限于浏览器，输出内容仅限于生成用例 |
| 放开AI能力 | Hermes智能体支持多种操作（操作系统、浏览器、接口测试等），应充分利用 |
| 保留生成用例 | 用户可选择是否生成用例，不需要时可不点击 |
| 高级感UI | 参考demo页面，重构后页面应更显高级感 |
| **动作转用例（核心差异）** | **Testory差异化优势：智能体执行动作后，可将动作转化为平台可维护、可复用的用例** |
| **视觉与思考同步** | **AI在执行过程中同时进行视觉识别和思考，实时生成测试用例** |
| **共享屏幕功能** | **AI可以识别用户屏幕内容，类似"共享屏幕"功能** |

### 1.2 Testory 差异化优势

Testory 与其他本地智能体工具的核心区别：

| 对比项 | 其他智能体工具 | Testory |
|--------|---------------|---------|
| 执行方式 | 仅执行操作，无后续价值 | 执行操作 + **转化为可维护用例** |
| 用例管理 | 无 | 平台统一管理，支持版本控制、复用、分享 |
| 执行结果 | 一次性执行 | 执行记录 + 用例生成 + 问题追踪 |
| 持续价值 | 有限 | 用例可重复执行、持续维护、逐步完善 |
| 视觉感知 | 无 | **AI可"看到"屏幕内容，同步生成用例** |

### 1.3 核心技术挑战

| 挑战 | 描述 | 解决方案方向 |
|------|------|-------------|
| **视觉识别** | AI需要识别屏幕内容，理解当前状态 | 截图→OCR/视觉模型→结构化信息 |
| **同步思考** | 执行与思考同时进行，不阻塞执行 | 异步思考+实时用例生成 |
| **实时用例生成** | 在执行过程中实时生成符合平台格式的用例 | 增量用例构建+状态追踪 |
| **屏幕共享** | AI可以看到用户的屏幕内容 | 屏幕捕获+实时传输+视觉分析 |

### 2.2 核心改进

| 改进项 | 描述 |
|--------|------|
| **移除画布** | 删除中间浏览器面板，AI直接操作本地浏览器 |
| **AI对话为主** | 中间区域改为AI对话界面，类似ChatGPT的交互方式 |
| **任务配置简化** | 左侧仅保留必要配置（项目、平台类型、推理引擎） |
| **任务结果面板** | 右侧显示思考流程、执行动作、实时用例、执行报告、屏幕快照 |
| **快捷操作** | 提供"执行"、"生成用例"、"动作转用例"三个核心按钮 |

| **视觉识别** | AI可识别屏幕内容，同步生成用例 |
| **共享屏幕** | AI可以看到用户的屏幕内容，进行视觉分析 |

### 2.3 视觉与思考同步流程

```
用户输入任务 → AI规划 → 执行动作 → 屏幕截图 → 视觉识别 → 同步思考 → 实时生成用例 → 保存到项目
```

具体步骤：

1. **AI规划**：分析用户需求，制定执行计划
2. **执行动作**：AI执行操作（浏览器、桌面、接口等）
3. **屏幕截图**：自动捕获当前屏幕状态
4. **视觉识别**：OCR识别文本、视觉模型分析界面结构
5. **同步思考**：AI基于视觉信息进行推理和分析
6. **实时用例生成**：根据执行动作和视觉识别结果，实时生成测试用例
7. **保存到项目**：将生成的用例保存到指定项目

### 2.4 共享屏幕功能设计

```
用户开启共享屏幕 → 系统捕获屏幕 → 实时传输到AI → AI视觉分析 → 生成结构化信息 → 辅助用例生成
```

技术实现：

| 步骤 | 技术方案 |
|------|----------|
| 屏幕捕获 | Windows API（BitBlt）/ Python mss库 |
| 图像压缩 | JPEG/WebP压缩，降低传输带宽 |
| 实时传输 | HTTP轮询 / WebSocket |
| 视觉识别 | OCR（Tesseract）+ 视觉模型（如LLaVA） |
| 结构化输出 | JSON格式，包含元素位置、文本内容、界面结构 |

#### 4.2.2 视觉识别流程

```python
def analyze_screen(image_path):
    """
    分析屏幕内容，返回结构化信息
    """
    # 1. OCR识别文本
    text_result = ocr_recognize(image_path)
    
    # 2. 视觉模型分析界面结构
    vision_result = vision_analyze(image_path)
    
    # 3. 元素定位提取
    elements = extract_elements(vision_result)
    
    # 4. 结构化输出
    return {
        'text': text_result,
        'elements': elements,
        'screenshot': image_path,
        'timestamp': datetime.now(),
    }
```

#### 4.2.3 同步思考与用例生成

```python
def execute_with_vision(task, project_id):
    """
    执行任务并同步生成用例（含视觉识别）
    """
    case_steps = []
    
    for action in task.actions:
        # 1. 执行动作
        result = execute_action(action)
        
        # 2. 记录动作
        record_action(action, result)
        
        # 3. 屏幕截图（如果开启视觉）
        if vision_enabled:
            screenshot = capture_screen()
            vision_info = analyze_screen(screenshot)
        else:
            vision_info = None
        
        # 4. 同步生成用例步骤
        case_step = generate_case_step(action, result, vision_info)
        case_steps.append(case_step)
        
        # 5. 实时推送用例步骤到前端
        push_case_step(case_step)
    
    # 6. 完成后保存完整用例
    case = {
        'name': task.name,
        'project_id': project_id,
        'steps': case_steps,
        'created_by': 'ai',
        'source_type': 'agent_execution_with_vision',
    }
    
    return save_case(case)
```

#### 4.2.4 动作转用例逻辑

每个执行动作记录以下信息：

| 字段 | 类型 | 说明 |
|------|------|------|
| action_id | string | 动作唯一ID |
| action_type | string | 操作类型（click/input/navigate/api等） |
| target | string | 目标元素/URL/接口 |
| locator | string | 元素定位器 |
| input_data | any | 输入数据 |
| result | any | 执行结果 |
| status | string | 执行状态（success/fail/skipped） |
| timestamp | datetime | 执行时间 |
| screenshot | string | 执行时的屏幕截图（可选） |
| vision_info | any | 视觉识别结果（可选） |

#### 4.2.5 用例格式转换

| AI动作类型 | 平台用例步骤 | 视觉信息用途 |
|-----------|-------------|-------------|
| navigate(url) | 打开URL步骤 | 验证页面标题 |
| click(locator) | 点击步骤 | 确认点击目标元素 |
| input(locator, value) | 输入步骤 | 验证输入内容 |
| wait_for(locator) | 等待步骤 | 确认元素出现 |
| assert_text(locator, text) | 断言步骤 | OCR验证文本 |
| api_request(method, url, body) | 接口请求步骤 | 不适用 |
