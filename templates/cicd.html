CI/CD 集成

支持双向对接与统一门禁：Jenkins ↔ Testory 通过/失败可同步到同一 sync 会话。 契约：docs/CICD_INTEGRATION.md §2.6。

两种方向怎么选？

  • Jenkins → Testory（推荐主路径）：流水线调用 POST /api/ci/runs，再 POST /api/ci/sync 绑定，或 Job 末尾 POST /api/ci/sync/<id>/jenkins 回写结果。
  • Testory → Jenkins：本页「统一门禁」或「触发 Jenkins」让 Jenkins 受理构建；平台轮询 Job 结果，与 Testory 终态合并为 unified_gate_passed。

流水线调用示例

            
在 CI 中调用（需 API Token 或登录态）：

            
POST /api/ci/runs
Authorization: Bearer <API_TOKEN>
Content-Type: application/json

{
  "project_id": 1,
  "async": true,
  "build_id": "$BUILD_NUMBER",
  "trigger_source": "jenkins",
  "callback_url": "https://ci.example/hook"
}

# 轮询
GET /api/ci/runs/<run_id>
# JUnit
GET /api/ci/runs/<run_id>/junit.xml

            

                执行结果会写入「运行历史」，并显示 build 徽章；可在历史中导出证据包。
            

        

    


    

        
统一门禁（Testory ↔ Jenkins 同步）

        

            默认策略 both_must_pass：两侧都终态后，仅当 Testory gate_passed 且 Jenkins SUCCESS 时统一门禁为绿。
            Jenkins 受理构建后会轮询结果；Testory 终态会回写同步会话（并可写入 Jenkins build 描述）。
