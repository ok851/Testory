按顺序列出步骤

用 "1. ... 2. ... 3. ..." 编号描述业务流程，AI 会按顺序分解为执行阶段。

2
指定操作平台

明确每个步骤在哪个平台执行：API 接口、浏览器页面、移动端 App、桌面应用。

3
说明数据流转

如 "API 返回的 token 用于浏览器登录"——AI 会自动处理变量透传。

4
添加清理步骤

如 "通过 API 删除测试数据"，AI 会自动标记为清理阶段，执行后自动运行。

!
写清要点击的控件

Web 步骤必须有元素定位（按钮文案/输入框名称）。空选择器会直接失败，不会假装通过。

↔
写清变量怎么传

如「把 API 返回的 token 用于浏览器登录」。缺变量时会提示等待超时，并说明该检查上一阶段抽取。

AI
可选 Hermes 执行器

默认用经典步骤（selector）。仅当阶段写明 executor: hermes 或 use_hermes 时才走 Agent；不可用会明确失败，不会假装跑过。

=
写清要对齐的数据

如「断言 API 余额与浏览器页面余额一致」。系统会比对多端变量；缺来源或数值不一致会明确失败。

👥
多 Agent 执行

分解后点「多 Agent 执行」：规划 → 执行 → 验证。下方时间线会显示各角色派单/完成，Verifier 报告标明证据强弱；未通过不会假绿。

PC
Windows 桌面阶段

执行前自动预检 Gateway/本机会话；不可用 → DESKTOP_NO_SESSION，不假绿。推荐「桌面主路径（记事本）」一键加载标准计划。

示例 — 完整描述： 1. 通过 API 注册新用户，记录返回的 userId 和 token
2. 在浏览器中打开登录页，用 token 注入浏览器登录
3. 验证首页显示的用户名与注册时一致
4. 在移动端用同一账号登录，检查订单列表一致
5. 清理：通过 API 删除测试用户
